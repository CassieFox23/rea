# Environment variables

REA reads these settings from the environment of the process that runs it. For
the CLI that is your shell. For the MCP server it is the `env` block of the
agent's MCP registration, as in the [IDA guide](ida-provider.md).

Paths marked "absolute" must start at the filesystem root, and REA rejects a
relative path. REA installs none of the tools these paths point to. Each row
lists the source files. The first one names the variable; any others use its
value, so you can check the exact rules there.

## Not listed here

- REA sets a few variables itself for the processes it starts. Do not set
  them: `REA_PROCESS_RUN_ID` (`src/process/ProviderProcess.ts`; REA rejects it
  in a caller's environment), `REA_CORE_CONTEXT_REQUEST`
  (`bridge/pwndbg/launch_impl.py`) and `REA_PACKAGE_VERSION`
  (`scripts/rea.mjs`). The names `REA_SOCKET`, `REA_TOKEN`, `REA_RUN_ID`,
  `REA_TARGET_PATH` and `REA_OWNS_PROCESS_LIFETIME` are written into the Hopper
  bridge script by `src/hopper/BridgeLauncher.ts`; they are not environment
  variables. `REA_BUILD_COMMIT` is reported as `build_commit` in the server
  identity (`src/serverIdentity.ts`).
- Variables that only tests and verifiers read, such as `REA_VERIFY_*`, are in
  the [testing guide](testing.md).
- Setup and `rea doctor` also read each agent's own configuration variables,
  such as `CODEX_HOME`, to find its config files. Those belong to the agents.
